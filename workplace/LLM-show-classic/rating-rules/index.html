# 当前角色的原生接口：显式作者输入

本接口共用于普通衣橱、导出与Review的 `classic-layers.mjs`。它不修改原生素材或原生100分基准，不证明任何新姿态已经98分。本轮只实现源码和staging；没有public apply。

## A：原生低位道具对应的AI上装/手臂

作者可在自己的profile中提供完整SVG：

```js
nativeLayers: {
  prop: nativeDisplayProp,
  top: {body: nativeTopBody, arms: nativeLowArms, bodyZ: 50, armsZ: 101},
}
```

`top`也可为包含完整衣身与手臂的单个SVG字符串。对象形式要求body、arms都真实提供且可见；没有自动沿用标准姿态手臂的分支。默认bodyZ50、armsZ101；z可由作者明确设置为0..120整数。单体top在top槽层级绘制。分层时须实际检查道具/发束/前臂前后关系，不能仅因默认z就认定接触正确。

`renderRemake`产出native-top PNG/SVG及各子层；root未来显式apply时保存top-native及子层，并设置 `variantRole:native-display`、`compatibilityPolicy:native-prop-top-v1`。只有当前AI top与所选prop.characterId为native时才使用它。hide只改变可见性，不改变所选prop身份；隐藏道具不会切回另一套手臂。两槽皆AI时仍使用标准立绘own top。完整native top会替换整套own top层，绝不叠加标准top-arms。

此top是作者选择的真实兼容姿态，**不自动证明全部15个原生道具都能正确持握**。每例仍须看接触点、手指和物体支撑并独立评98；不同道具位置不能靠无限延指或移动原生物解决。本轮不增加逐prop变体；确有必要时再按源指纹扩展。

无真实src/PNG hash、缺失子层hash或未提供新top的角色没有此兼容资格。当前没有flag的角色仍走原行为，不能退回历史standing。staging中使用冻结own SVG的渲染诊断只证明分层/选择路径，不是低位持物艺术稿，不能作为接入示例成品或直接apply。

## B：AI裙×原生腿的作者接触色簇

```text
node tools/classic-contact-interfaces.mjs gemini
```

读取真实冻结manifest、cfd原生池，写 `previews/classic-compatibility/gemini/` 中15源1x/4x前后图、输入模板和provenance。默认没有自动画影算法：所有模板 `enabled:false, placeholder:true`，不加入实际item，不改变family或v4签名，也不证明缝隙已修复。

作者在该目录另写authored.json，或在自己的profile.nativeLegInterfaces中提供同样的逐源记录：

```js
nativeLegInterfaces: {
  'native-lower-3': {
    enabled: true, placeholder: false,
    inputs: /* 原样复制当前templates.json的真实指纹 */,
    inputDigest: /* 对应SHA256，不能沿用旧bottom的值 */,
    regions: [[70, 156, 10, 4]], // 仅是语法示意，必须按该源实际衣摆确认
    maxDepth: 4,
    palette: ['#df9045', '#fdc68f'], // 必须来自该源或真实default可见腿调色
    contactSvg: authoredContactMarkup, // 真实非空色簇，不能启用透明模板
  },
}
```

检查冻结输入后可用 `node tools/classic-contact-interfaces.mjs gemini --authored` 生成候选；程序只读固定目录的authored.json。实际source/regions/palette须从真实图确认，示意值不表示适配所有源。

色簇不得用blur/filter/random noise。当前验证限制：1..4个原生坐标小矩形、总面积不超过192；实际色簇不超过96像素、最多4个原生RGB色、单色连续横段不超过8像素。像素必须落在真实腿或既有隐藏支持像素内，并在当前AI衣料下方最多4原生像素的接触范围。此限制仅约束来源和局部性，不是审美评分器；不合适的阴影仍可被独立judge否决。

产生的interface合成“既有derived hiddenPatch＋作者contactTone”，归AI bottom所有；允许覆盖混搭中的腿部接触处，但绝不改原生文件、原生originalFull或两槽皆原生的图。即使原hiddenPatch.pixels为0，真实已校验的作者contact仍可独立选中。两槽皆AI时不注入；没有有效opt-in仍原v4桥层行为。

## C：AI 上衣与原生裤裙腰线的作者接触

R15 `upper2` 五套实际组合确认相同衣尖在高腰牛仔、抬膝裙上仍需局部厚度。作者可提供 `profile.nativeBottomTopContacts[sourceKey]`；这与 A 的整套持物姿态分开，仅增加 z49 的局部翻边/压影，保留 own top-body50 与手臂。只有所选 bottom 为指纹匹配的原生来源时注入，hide 不改变该身份；全 AI 立绘与原生 100 均不注入。

`upperContactInputs(topBodyArtworkHash,native)` 输出有序输入 `{topBodyArtworkHash,nativeSourceKey,nativeSourceRawHash,nativeVisibleBottomHash,algorithmVersion:'authored-top-hem-clusters-v1'}`；`inputDigest` 为此 JSON SHA256。使用真实 top-body PNG，不能用 familyHash 或合并 top PNG。若 A 换成不同 body 子层，旧 C 不匹配，须另画，不能串用。

作者输入含 `enabled:true, placeholder:false, inputs, inputDigest, regions, maxDistance:4, palette, contactSvg`，工具 `renderNativeBottomTopContacts` 只做来源/局部性校验，不自动绘影。限制 1..4 个小矩形，总面积≤256、每矩形宽≤32高≤8、y104..160；实际≤96像素、单色横段≤8；≤6个精确RGB来自当前上衣或该原生lower。像素须在实际上衣边≤4像素并接近原生lower原件≤1像素。空模板禁用，输出 `authored-top-contact-candidate`、`ai-top-native-bottom-contact-v1`、PNG/SVG、源/摘要/作者记录。

`renderRemake` 保存各 source 的 top-contact PNG/design/JSON，显式 selected apply 才写 public。family 仅有效非空 C 新增输入/输出/z/policy；actualAiLayers 和 generatedInterfaceHashes 将 C 归 `AI top`，必须与原生组合共同独立评98，不能继承100或仅凭局部性校验宣称修好。root 对新 hook 的实际当前653组选择与56版族核对均0变化（尚无角色 opt-in，见 previews/classic-compatibility/root-audit/upper-contact-preservation.json）。实际作者图接入后另做真实15源/React审阅。

## B 与共同输入的版族

输入包含bottom自身PNG hash（不使用reviewFamilyHash）、native sourceKey/rawHash、真实unfilled腿hash、原隐藏patch hash、算法版本authored-contact-clusters-v1。inputKey为约定字段JSON，inputDigest为其SHA256；作者管线验证摘要，浏览器同步解析器逐字段匹配当前真实输入和inputKey。更换原生源、改底PNG或改算法不会挪用旧interface。

family payload保留旧 `{own, ownLayers, native}` 的键序；只对真实opt-in增加native-top子层/z/policy或active authored interfaces的输出hash、contact hash、inputs、digest。无flag或全disabled模板保持原family hash。interface输入不引用family hash，因此没有family→interface→family的循环。

## 1. 冻结当前绘制版本

各角色模块为`tools/classic-remake/{id}.mjs`。作者只写自己的模块和私有revision；root核作者已停笔后统一导入，不能全量import正在修改的其他作者模块。以下命令工作目录为`D:/LLM-show/LLM-show-classic`，角色名单仅为示例：

```powershell
node tools/archive-classic-runtime.mjs
node tools/remake-classic.mjs gpt deepseek glm --apply-selected --render-root=ai-workspace/previews/classic/remake/apply-import-r25
node tools/build-classic-native-review.mjs --reuse-native-pool
```

`--apply-selected`显式命名1～6位已停笔作者，只import/render这些人；七位全部已停笔时才可用全量`--apply`，两种flag互斥。`--render-root=`是可选的独立导入目录，须位于项目`ai-workspace/previews`内，批次应清楚可追溯；默认导出API保持原行为，body/construction指针必须跟随实际输出。旧预览被占用时保留旧图并生成新批次，不拿旧construction冒充新稿。

导入后用`tools/record-classic-selected-freeze.mjs`记录前置归档ID与本次冻结JSON，核未选角色metadata/items和逐文件SHA不变、原default逐像素差0、五个源哈希未变、七人运行时完整、原生pool/corpus不变。selected apply不刷新七人总作者板/gallery，以免读取其他作者草稿；这些总板可能历史，正式评审以冻结运行时和实际React为准。

当前原生为217件：10槽各20件、背饰17件，保留扩容前165件的PNG字节与来源。新增下装的源同坐标重合成与独立QC继续留档；普通美术改稿复用`--reuse-native-pool`，不要无故重建原生池。确需改池时另核真实性和完整性，poolHash变化后重新取证。当前工作索引为`ai-workspace/previews/classic/remake/HUMAN_FOLLOWUP_STATE.json`，具体版本以manifest及冻结记录为准。

裙腿同源联动，`native-complete-torso-v1`按真实源alpha检查中央躯干连通，减少缺块；它不证明所有全身组合、手掌、发脸及衣料接触均已自然。不得按AI成绩筛seed、排除难样例或降低原生100。

源专属mask或隐藏补片有变化时，先独立QC新增露出部分。同源重合成0差只说明原衣物遮住了修改，不能替代自然体块审阅；新增桥接或补画属于AI接口，绑定哈希评98，不继承原生100。

archive工具保存已apply运行时及原生池所引用的准确PNG/SVG/GIF/Markdown、清单和评分，逐文件SHA核对。位置为`results/archived/runtime/{archiveId}/public`；原URL在该public根下定位。运行时归档、作者源码快照和真实React截图分别保留，不能互相替代。

`manifest.remake.characters`保留completeHash/bodyHash/artworkHashes及冻结bodySrc/bodySvg；各AI槽及ownVariant含artworkHash，body副本带bodyArtworkHash。builder优先取已apply PNG，只在哈希匹配时允许cache/作者preview恢复，绝不把未apply草稿当本轮body。`tools/freeze-classic-review-bodies.mjs`仅恢复与已apply哈希相同的中间产物。单部件不能只绑定成品hash，因为被衣裙遮住的修改未必改变成品。

### 逐张核对实际位图（本期补充）

本次已证实：同一次CUA调用里批量滚动、连续截图可能复用上一张位图。DOM已经ready、`naturalWidth>0`、`failedImages=0`或metadata声称目标可见，都不足以证明回包PNG就是该目标；不同SHA也不能单独证明内容正确。

- 滚动/定位与截图分开，**每张截图独立一次CUA调用**。截图回包后实际打开PNG核对，确认正确后再前进，不能在同call循环中批量滚动截图。
- body图读取实际`#01–#20`标题，并核原生人物/服装/姿态身份与冻结corpus一致。只露出目标标题而没有目标完整人物，不能计作目标覆盖。
- matrix图核实际“原生N”、对应fixture和footer原生部件ID，逐项对照case/nativeSelection，并确认原生与AI两侧对应同一上下文；不能仅信DOM visible ID。
- 实际编号/身份确认写入`rasterConfirmation`等记录后才可计有效范围。相同SHA被赋给互斥ID时应触发内容复查，但错位结论仍来自实际PNG，而非只由哈希推断。
- 失效PNG、原metadata、SHA和不一致原因保留，标记`validForReview:false`；按相同seed、context、当前艺术hash补图，记录替代关系。技术补证不另计美术修改轮数，也不改变美术评分或清历史问题。

## 6. 修改后复评与未变范围携带

新增素材须核实际服务响应：正确image MIME/字节、加载完成、naturalWidth与failedImages。历史上出现过磁盘有图但HTTP200返回SPA HTML的故障；当前`../frontend/workspace-files.mjs`动态解析受控运行时路径并核真实文件，不能保留“每新增图必重启Vite”的旧做法。技术失败先查当前响应与源，保留失败证据并按相同seed/draws重采；艺术失败的新一轮按当前217件池取新seed，不换有利组合洗分。

## 本轮重点：肢体手掌、发型刘海与衣装（2026-11-10 用户追加）

体块审计首先检查肢体与手掌的自然度：肩—上臂—肘—前臂的外廓收放、连续转面，腕—掌—拇指/指群的过渡、屈伸和受力，以及手与书/碗/扇/包链/斧柄等实际接触。避免尖V肘、等宽直杆、几何关节、方块掌、圆洞掌、梳齿指群或断开的掌根。140×226允许原生式手指概括，不强迫每指逐根可数；概括仍须结构合理、轮廓自然。裸模和穿衣/手套状态必须同时看，不能用衣袖遮住不合格手臂或手掌。

重点反例应尽量并列同尺度、相近屈伸/接触的真实原生局部作100参照，记录来源和裁框；不变形放大、不用裸模未知区域虚构真值。原生本来也有的紧凑指群、适度负形、局部直边和合理关节像素角阶，本身不扣分；“尖V/杆/洞”等描述须指出AI额外引入或加剧的真实结构/转面/遮挡缺陷，不能套写实五指或光滑曲线标准。此校准不改变98门槛，也不豁免可见的不自然连接。

2026-11-10用户进一步强调肢体不饱满、呈“骷髅兵”感：必须检查肩臂肌腹、肘前后转面、前臂近端、腕掌/掌跟等是否有真实饱满的肉面和自然收放；不能只剩骨点间的细杆、细轮廓上加纹理或统一描粗外边。也不能为穿过旧画布测线、单条截面或未确定的对应点而削掉合理肉面。可直接比较的真实体量守门仍按下文执行，姿态/对应/重叠不明确须先复核，不以测点数字替代可见自然度。

同次用户强调Blingee Pixel应当华丽而层次、线条分明。发束主谷/转面/分叉，衣褶主暗面/折谷/亮峰，以及袖腔、掌指、道具和裙层的前后遮挡必须在原生1×清楚可读；细密像素与丰富色阶不能糊成一片。碎亮点堆叠、低对比半调混合、全局模糊或锐化、更多闪光均不能代替清楚的形体和层级。融合分照既有像素笔触、体块、材质、Blingee协调和遮挡维度记录，不改权重/98门槛；须给具体糊合区和真实原生同尺度对照。

接触审计先看原图与原生部件真实语义：明确握持/支撑的书、碗、扇、柄、包链须有合理掌指接触；立式麦克风、设定中悬浮的物件、腰饰或胸针不强求手握。不得仅凭手没握住原生装饰就扣AI分；须在上下行对照中定位AI引入或加剧的真实穿插、断接或接触缺陷。原生基准仍100，不能降低其分数，也不能用此条豁免AI自身的实际错误。

发型、刘海和衣服必须双向重点评价：既看与normal的发型轮廓/分缝/刘海方向与长短、标志衣型/袖口/裙层/褶向/对应色相的还原，也看其在真实原生组合中的像素尺度、暗边/发丝簇、材料色面与接触遮挡是否融入。不能用较好的还原分替代融合，也不能为融合把标志刘海或衣型改没。normal原本有意遮眼的刘海按其真实设定审，不把准确的有意遮盖误当技术错误。

### 素体专项守门

独立短预审即使 `requiresRevision:false`，若明确 `requiresFurtherAudit:true`，当前素体仍为 pending，不显示通过。它可以支持把已停候选冻结到验收台供实际 default＋20/全套审阅，但不能替代未覆盖区域的最终判断。既有确认问题可由明确 resolvesBodyHashes 清除，尚待复核的范围与不利观察继续保留。

同一 bodyHash 补完短预审后，独立报告须明确 `requiresFurtherAudit:false`，并在 `resolvesFurtherAuditReports` 列出被完成的预审 `sourceReport` 路径；不是靠较新的日期覆盖旧待评项。发现真实差异则仍记 requiresRevision，不用“范围补齐”清除确认问题。

用户原话要求与20张不同姿态、着装原生样例相比，不能有“5%以上能明显感知到的差异”，并未指定所有姿态的某条骨宽必须相同。原话定位见 [验收要求来源](USER_CRITERIA_PROVENANCE_20261110.json)，方法独立复核见 [报告](../ai-workspace/previews/classic/remake/acceptance/human-followup-20261110/default-point-method-independent-review.md)。直接可比部位采用统一法向量测作为辅助，不能以不同姿态的横截面混比，也不能把28个点外推成全身≤5%。统一的是源图、坐标、alpha和采样口径：原生140×226、双线性alpha>128、0.025px法向采样。default上臂中心(56,104)、轴(-1,12)、宽5.025；前臂中心(48,119)、轴(-11,10)、宽4.825，仅为这两个源截面的观测值，不是全部角色/姿态的目标宽度。记录实际采样部件、中心、轴和哈希；数值宽差不能直接等同可感知差异或审美分。

单线超过5%须如实保留为不利诊断。只有同解剖、同可见成分及投影对应成立，锚点/相位/重采样控制支持持续真实局部体量差异，并能以同尺度原生1×/整数倍对照指出可感知缺陷，才列确定返工项；否则注明待对应或不可比的具体范围，不能统一缩臂、削肉过点。衣料腰胯只标proxy。即使量测通过，细杆肢体、掌跟薄、断续暗边、手掌橙块、行位移刺、关节拼接等目视缺陷仍可否决98。原生default皮肤应成面、连续有覆盖度，不能仅全局crisp.65造成点线后宣布风格一致。

视觉分与尺寸守门独立。真实default＋20的专家98保留其来源；若随后独立量测确认同一body hash仍有真实可比体量超差，该素体仍需返工，不能凭98覆盖新证据。`classic-anatomical-leg-audit-v1`只记录技术发现，不生成或改写审美分：由`classic_body_judge`给出`characters[{id,reviewedBodyHash,requiresRevision,confirmedFindings,evidence}]`，先区分确定差异、相位/映射疑项和未覆盖部位。导入器按当前exact body hash附加阻断；同hash任何未解确认项不被新seed/另一个较好点洗掉。React保留视觉数值并明确显示“形体需返工”，不显示整体通过；改几何后须新hash和复审。没有确认阻断仅代表该次明确范围，不是全身数学误差证明。

换body hash也不自动解除已知问题。某角色有历史确认的尺寸阻断时，新body必须由独立audit以`requiresRevision:false`、当前`reviewedBodyHash`及`resolvesBodyHashes:[此前确认问题的body hash,…]`明确解除；未覆盖全部历史确认项就保持“形体待复核”，不得因为无关手部改色或改名洗掉小腿问题。原同hash确认阻断始终优先，不会被同hash另一个false结论覆盖。`classic-body-audit.mjs`让React与最终汇总共用该规则，仍不生成审美分。

当前素体还必须有独立的可比可见体量复核记录；`not-reviewed`保持待审，不能只因视觉default20都98就显示整个素体验收通过。只审主四臂点、视觉足部或仅给无尺寸问题结论而不保源/目标/对应/控制证据，不满足这个补充守门。审查范围与未覆盖裸模未知区域必须如实写明；没有官方裸腰胯时不编造其尺寸真值。该规则不修改原视觉分，不把不能直接对应的不同pose硬当误差。

独立复核先审核方法适用性，不要求对衣遮/未知裸模捏造数值。原始技术记录永久保留，方法纠正与几何修复分别留档；本次方法说明、同hash新false或换hash都不自动清旧项。须逐finding独立复核确证、待对应和不可比范围，保留不利主线/窗口、源/目标/控制及未覆盖项。稳定同解剖且可感知的真实缺陷仍须返工；仅与default单点数字不同不能独立证明用户不合格。

量测坐标须注明是PNG数组索引中心还是SVG物理坐标。数组索引(x,y)对应SVG物理(x+.5,y+.5)；从raw像素中心反推的source中心线已是数组口径，手写target SVG曲线则须换算−(.5,.5)。不能对某方重复修正，也不能把正确换算当作任意挪有利点。保留raw/换算后、不利邻域与选点依据。

不得仅用profile中估计的knee/ankle标签强判解剖误差。新增方法应先用实际字节相同的原生腿做恒等对照，再记录估计关节造成的误差，使用可见关节转面/原足映射及合理锚点敏感性核对。当前GPT c803…在x35–99/y146–225对default逐RGBA/alpha0差，正确同解剖raw/平滑主线与窗全0；故意套不精确profile膝踝会造左+8.70%、右−9.73%单线及右邻窗超5假差。对其他身体必须区分这个定位误差与在合理锚点范围仍持续的真量差。

主点之外保留邻域多线/窗口敏感性，必要时用真实原生calf在相同局部曲率、切线及有依据的骨段投影长度下、法向宽不变的控制来校准像素采样。nearest/bilinear、等长rigid与沿轴投影控制要分别标清。控制图不自动成为生产美术或原生100参考，更不自动授98；窗口过关不能直接抹掉单线，不同局部曲率的简单全局旋转控制也不能假装完全同pose。只把不能由这些误差解释、解剖对应成立的持续超差列为确定返工项，保留其余未知，不挑有利点。

“固定采样”固定的是基准、骨段及其归一化解剖位置，不是要求所有新pose永远穿过旧画布坐标。若为还原立绘真正旋转/外展骨段，保留旧点作为回归记录，同时明确旧→新中心/切线的姿态变换，在新骨段对应位置沿真实法向再测；两套结果和选点理由都留档。不能用旧点附近恰好的连通片代替新pose体量，也不能任意挪点只挑合格断面。独立评审可追加邻近同解剖断面，不能让尺寸约束反过来破坏立绘动作与连续自然体形。用户的可感知差异5%要求不变；数值诊断须遵守上述适用域，量测始终不授审美98。

## 维度二：整套立绘还原（门槛90）

### 颜色还原：色相接近（2026-11-10 用户最终澄清，必评）

只重点评价对应部位的色相是否接近本套选定 normal 立绘（或用户明确确认的配色适配）。逐项核对发色、渐变两端的色相、左右瞳色、衣裙鞋袜和配饰的对应色相。不能把应为蓝、紫、银灰、金、红等颜色明显画成另一色相；主色或辅色要对应到正确部位。

具体RGB/HEX色号、明暗、饱和度不作为还原评分的重点，不因合理差异扣分；允许按原生Classic像素材料调整色阶、光影、对比和饱和度。这些光影/材质是否自然，仍在融合维度评价，不能反过来要求复制立绘精确色值。也不设置面积比例或颜色数值误差门槛。

保持六维权重：发色/渐变色相计入「刘海和发型」，瞳色色相计入「神态」，衣裙鞋袜色相计入「服装」，配件色相计入「配饰」。同一色相问题只在所属维度扣一次。正式全套报告的 colorFidelity 观察项记录参考图、已授权适配、对应部位色相差异及扣分归属；不得仅作不影响评分的附注。旧报告缺本项时，该范围保持未覆盖，不补造旧分。

角色N/A与姿态变体不同：Claude、Qwen无独立back仍是N/A，不为该槽新画道具。nativeLayers现另支持作者完整top，或top:{body,arms,bodyZ?,armsZ?}；仅选当前AI top且所选prop来自native时使用，hide不改变所选身份。它会替换整套own衣身/手臂，不自动叠加own arms；没有显式真实top的角色不变。原生道具位置不同，每例仍须独立评98，不能延指或移动原生物代替适配。完整契约与staging范例见[COMPATIBILITY_INTERFACES.md](COMPATIBILITY_INTERFACES.md)。

新top的native子层/z及native-prop-top-v1 policy绑定family；逐原生腿的AI-owned authored contact interface也可显式输入，输入摘要不引用family，避免循环。新policy只在实际opt-in的选择上启用v5证据签名；无flag仍原v3/v4，透明disabled模板不改变当前角色或历史评分。
# 完整成品哈希的文件口径

`completeHash`绑定`character.png`：十层各自以原生尺寸PNG渲染后按运行时层次合成，与React实际逐PNG层一致。`04-complete.png`是单份合并设计SVG的阶段渲染，跨层抗锯齿/透明合成可能给出不同字节，不能把它的SHA冒作运行时completeHash；`04-complete-design.svg`保留可编辑设计用途。bodyHash则绑定真正冻结body PNG。报告须明确文件名，不只写含混“full hash”。例如Grok R3阶段04为b5192092…，canonical `character.png`/manifest为270ec635…，不是运行时版本漂移。
