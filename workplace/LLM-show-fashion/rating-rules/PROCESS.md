# 抽样、审阅与反馈流程

本流程适用于下次评分，不要求先重画角色，也不自动授权生成新轮或恢复已删除归档。分数遵循[评分细则](SCORING.md)，返修授权遵循[协作规则](ITERATION_RULES.md)。

## 1. 评分前先确认输入

记录角色ID、评委、目标版本、轮次、seed、inputHash、nativeHash、renderModelHash及本次规则SHA。标准图必须是对应角色atlas MD所链接的初始正常比例立绘；当前工程使用ZipZipPipe版本，不能混用校园/工程服/其他作者图。

逐项检查实际存在的session、catalog、模型、SVG、标准JPG、完整MD、案例和截图。优先检查现有runtime快照、results当前版本及workspace报告；不能因路径写在旧文档里就假设文件还在。input、模型、原生或参考版本不一致，不能沿用原结论。

下次可先从以下位置找资料；必须读取内容与SHA，不能只看文件名：

| 资料 | 工程内入口 |
| --- | --- |
| 冻结session及其catalog/model引用 | ai-workspace/runtime/review-rounds/round-N/session.json |
| 当前三版案例索引 | results/{newest,new,previous}/{id}/rating/cases.json |
| 对应标准体索引 | 同目录standard-study/study.json及其图、原源 |
| 角色组件、JPG与MD | 当前版本src目录，以及冻结catalog指向的原文件 |
| 独立报告和浏览器账本 | ai-workspace/workspace/reviews及当前版本rating目录 |

本次整理时，newest七位的cases.json与study.json均仍存在（六位R39、DeepSeek R38）；这里只确认这些索引可用，不声称其引用文件都已重新审阅。它们是现有副本，不必为找到评分输入恢复已删归档。旧脚本/页面若仍依赖被删路径，则先核实可用路线；不能把“副本存在”当成“原工具已经可运行”。

用户已删除results/archived。旧案例/归档session不存在时，不运行依赖它们的命令并假称完成，也不擅自重建。可用运行快照只证明其实际保留的范围；缺少的输入、案例或参考逐项登记。若新评分任务授权生成补充证据，使用明确的新评审标识和来源，不伪装成恢复了旧轮评分证据。

同一艺术快照可以另开新的评审记录，不必为重新打分创建新资产轮。记录艺术快照轮次与本次规则SHA；采用现行规则与旧快照规则不同时明示，不覆盖原评分或假称规则从未改变。

人评按原文及当时版本清单解释，不能随着newest变化而转移对象。标准图/MD和人评内容是评价依据，不构成修改代码、继续绘制或发布的授权。

## 2. 先保证原生上下文可比较

- 使用14主槽及7解剖子槽；原生候选目标沿用10–20个，优先增加真实独立几何。实际不足如实记数，不能平移、换色、换标签凑数。数量、来源和覆盖从当前目录核实，不把上期244/216等快照数字当永久事实。
- 每轮取五组整体完整的原生着装：前后发配套、脸/五官来源相容、上下体/手/鞋位完整。可选背饰、头饰、持物和点缀允许不佩戴，空选择不是新增组件。
- 优先使用实际观察过的身体/上衣/下装三元组及身体/鞋随动关系。观察表须绑定当前native/model及证据SHA，不能将已看的一组扩成笛卡尔兼容全集。
- 完整性筛选先独立检查原生，不得因某AI件在有效原生下失败而删掉该上下文，也不能只挑有利服装掩盖AI接面。
- 原生缺块或错搭仍按原生100校准，状态记为invalid_native_context；当前对照不足以判断的AI项不编分。保留原因，不删难例、不把问题转嫁给AI。修正上下文须保持旧证据不变，按任务授权另建明确输入。
- 不同轮次在允许抽新组合时使用新seed，保留已确认失败接口作额外回归；额外回归不能替代新抽五组。

原商品与语义派生件分开记录。腾讯原方案按商品物理层组装卸、处理身体区域占用，并按下装腿姿联动下身和鞋袜；透明占层与未知/缺失层不同。恢复时保留完整层组、腿姿/鞋位和来源，不把裁切派生件冒充正式完整商品。CDN空文件不能证明商品声明了透明层；当前观察白名单也不是官方商品元数据。研究说明见[原装配机制](../ai-workspace/workspace/research/compat-20261110/FINDINGS.md)，实际实现范围仍须检查当前模型。

## 3. 按顺序实际看图

### A. 全面首扫

先看完整成装、标准裸素体及21槽各一例，列出本轮全部明显低点。标准体直接看6x，逐处检查左右颈肩、肘、腕/掌根、腰髋、膝、踝；各记“连续”“确认问题”或“遮挡/未知”。不要只查上一轮失败的一侧。

### B. 低点归属与五语境复核

将疑似问题的完整原件、正确原生装配、当前AI、孤立件和相邻件并排。记录舞台坐标、源路径、裁切/刚性变换及遮挡，区分原生固有画法与AI重组的断缝、悬帽、双边或硬切。未读完整参与图层前，不将有意跨back/effect分层误报为断根。

每个目标至少看本轮五种有效原生上下文，并核其相邻和多AI场景。额外关注：

- 短裙/露腰时尾根是否连续到真实髋后，单选尾时是否仍成立。
- 原生短发下角根、耳根是否有支撑与自然遮挡，不能只靠自有长发遮住。
- 抬臂时袖根/袖口与真实前臂stub、腕掌是否连续。
- 原掌、手指和道具是否重复、悬空或断接，持物动作是否保持。
- 毛料是否形成连续厚簇与覆压，衣料是否沿肩胸腰胯/关节转面；细线、V刻纹、宽叶平片或方向突变的分段贴皮不能代替体积。

### C. 还原与补齐

对照完整标准JPG及MD，分别评动作/重心/手势、神态、发型、衣装、标志配饰和对应色相。标准姿态按立绘，兼容姿态按原生目标，不能相互代替；隐藏解剖只记不确定性。

已确认失败可提前出needs_repair或partial报告。低点消除后若要签完整接受，再补齐所有246案例及标准7视图/20原源/直接6x；少数接口通过不等于全角色通过。

## 4. 内置浏览器取证

- 使用ChatGPT内置浏览器IAB。可用性以实际打开页面为准；主agent可呈现、独立评委审阅保存截图，分别记录呈现者和审阅者。不能把工具名存在当成评委有provider，也不能将外部Chrome冒充IAB。
- 使用同一冻结session/catalog/model，实际叠SVG及鞋随动变换。不能把离线合成PNG放进网页就称真实叠层验收；离线图和源代码仅补其实际辅助范围。
- 等待目标角色、轮次、组号、focus和ready，同时确认参考JPG及所有参与图层解码。旧组仍ready不能算本组完成。
- **实际检查保存后的位图**：必须看到正确案例ID、完整人物/关节、双方基准与来源。DOM ready、decode、截图成功返回均不证明位图完整。载入中、JPG半截、只剩头栏、错误裁图、旧组残像不计覆盖。
- 截图失败先核实范围，可用fullPage或focus单面板。不能为凑覆盖反复无效取证；仍失败就登记缺口。失败图保留为排除记录，补图使用新文件，并注明替代关系。
- focus一张只计实际显示且独立看过的一个case。直接SVG6x可以分为原y=[0,452)、[452,904)、[904,1356)三条840×452无缩放横带；三带实际审全才计一次完整6x，不增加案例数。
- 记录查看器源码SHA、截图SHA、来源URL、input/native/model/seed、实际case ID和排除项。按ID集合去重，重复图、同一全套的多次截图不能重复算案例。
- 按“已生成→已呈现→已保存有效图→独立实际审阅”逐层记录。取证清单只证明采集，实际审阅账本才决定已审覆盖。

## 5. 固定覆盖与状态

| 内容 | 当前协议计划数 |
| --- | ---: |
| 21槽×5上下文 | 105 |
| 10相邻对×5上下文 | 50 |
| 18多AI组×5上下文（含解剖组合） | 90 |
| 全套AI对标准图 | 1 |
| 混搭合计 | 246 |

标准体7视图、20原SWF/SVG参照、直接6x另计；它们不进入246。该矩阵不是穷举所有手工搭配，协议变更必须说明，不能静默缩减分母。

| 状态 | 如何记录 |
| --- | --- |
| unreviewed 未审 | 无实际可评分观察，分数留空/null，不填0或98 |
| invalid_native_context 原生上下文无效 | 原生仍100；说明缺块/错搭及受影响案例，不编AI分 |
| needs_repair 确认失败 | 引用实际证据、坐标、低分或核心否决；其他未审仍留空 |
| partial_pass 部分通过 | 仅已审范围达到门槛；显示“已审最低”、数量/246及标准已审范围，整套accepted=false |
| accepted 完整接受 | 当前246全过、身份通过、标准7/20/6x完整且pose一致、浏览器证据有效 |

任一已审失败时，整体状态不能只写partial_pass；同时列失败和未审。标准体局部98只能写“所见局部98，标准未完整通过”。身份只有离线图可看时可给明确标注的辅助判断，但不能完成正式浏览器身份验收。

## 6. 可复制评分报告

以下是可读报告模板，不是可直接发布的机器JSON；未知项保持未审。现有发布器要求有限数值及正确证据绑定时，不得为通过校验填假分。

~~~markdown
# {角色} · {输入/轮次} · 独立评分

- 范围：只评分 / 另获授权可返修
- 本次评审标识：；艺术快照轮次：；采用规则与旧快照是否相同：
- 评委：；IAB呈现者：；实际审阅者：
- 绑定：inputHash / nativeHash / modelHash / seed / 规则SHA
- 参考：标准JPG版本及SHA / 完整MD版本及SHA / 人评基线版本
- 输入和证据缺口：
- 总状态：unreviewed / invalid_native_context / needs_repair / partial_pass / accepted

## 融合
- 已审最低：__；实际唯一case：__/246；未审case ID：
- 单件/相邻/多AI/全套分别已审范围：
- 五种原生语境是否有效：
- 每个已审case：ID、实际分数、理由、原生/AI图与截图SHA
- 确认问题：部件、舞台坐标、原生参照、AI新增差异、最小充分修法

## 立绘与设定
- 分数/状态：__；正式IAB证据 / 仅离线辅助 / 未审
- 动作20 + 神态15 + 发型头脸20 + 衣装25 + 标志特征20：
- poseAudit：立绘可见动作、当前对应、显著程度；遮挡/未知
- colorAudit：发/眼/衣料/耳角翼尾/持物对应色相、偏移方向、扣分归属
- 不以具体色号、明暗、饱和度、面积或渐变范围扣颜色还原分

## 标准完整素体
- 状态：未审 / 局部 / 完整；已审7视图：；已审20原源ID：
- 直接6x：完整图 / 三带已审编号；可见双侧关节逐项结论：
- 融合：__（明确局部或完整）；poseConsistent：true / false / 未知
- 标准完整pass：true / false；未覆盖项：

## 证据与结论
- IAB实际有效case ID；重复/失败排除；图像SHA/URL/查看器SHA
- 原件固有画法、AI重组缺陷、旧漏审、本轮新增分别说明
- 整套accepted：true / false；理由与尚需补审：
- 修改建议仅为意见；是否执行以当前用户授权与停止要求为准
~~~

返修任务得到授权时，反馈包同时交五张原生图、对应AI/接合图、完整标准JPG与MD、原源参照、case ID/seed/hash和精确意见，不能只发分数。仅评分或用户已停手时，写“建议留档，不自动执行”。
