# 协作、返修、版本与停止规则

评分门槛见[SCORING](SCORING.md)，实际步骤和模板见[PROCESS](PROCESS.md)。这些常设规则不自动恢复历史目标或解除阶段停止状态。

## 1. 先区分任务授权

- “评分/审校/整理规则”默认只完成观察、报告与指定文档，不自动修改角色、生成下一轮、构建或发布。
- 只有用户任务包含refine/remake/返修时，才在授权范围内交角色作者修改；不因出现低分就自行启动艺术迭代。
- 用户最新停止指令、轮次上限优先于既有计划。停止后只完成明确允许的本轮审阅和整理，缺陷留档，不为目标尚未全过而续跑。
- 不创建空轮凑次数、不重编号、不覆盖旧输入；全局评审轮次与角色R5/R6绘制稿号分开。
- 新任务是否允许新轮由该次指令决定；先检查现有iteration-limit状态，不擅自删除或放宽守卫。本次文档整理不修改该状态。

## 2. 专属作者与独立评委

GPT、DeepSeek、Claude、Grok、千问、Gemini、GLM各由专属refining agent负责其模块、产物和记录；并发不足可分批，不能省略某角色。主agent协调共享工具、原生上下文与反馈，独立评委实际看图评分，不替作者改画自证通过。

浏览器呈现和评分可以分工，但必须明确谁有IAB provider、谁保存有效位图、谁实际审阅；已生成/已截图不等于已审。结构、哈希、自动差异和来源审计可辅助，不生产美术分。

## 3. 获准返修时的闭环

1. 固定当前输入、标准JPG/完整MD、原生语境、模型、seed和规则版本，先审现图。
2. 首次反馈一次列全可见双侧关节及21槽首扫低点，再用五语境、相邻、多AI图和原源确证。不要每轮只查上一处、漏掉另一侧。
3. 交完整图证与具体case/坐标/源归属；明确原生固有画法、旧漏审、本轮新增、未审或遮挡未知。
4. 作者先修最低且归属明确的部位；保护其他已过设计、掌指/持物、鞋位和绑定。保护是控制改动，不是免审。
5. 需要时允许用相符完整母件重构，透明记录来源，不把“最小修正建议”误解为永远禁止重做。不得用服装或长发遮缺口来替代接口修复。
6. 真实导出、刷新输入hash；获准新轮时新seed，复核新组合并额外回归旧低点。不同input或模型不继承旧分。
7. 独评只签实际覆盖；关键低点消除后补全246及标准7/20/6x才可完整接受。未通过、未审或已停手时不抬分收尾。

## 4. 绘制与归属边界

允许以原Fashion身体、发型、布料、鞋/饰物的完整相符构件作母版，保留原路径/色片/渐变并局部重组、刚性摆位及重绘接根。记录原SWF、SHA、路径/shape、裁切/矩阵和自绘范围；借用或自绘本身都不自动加减分。

禁止全幅位图追踪、全身缩放/TPS等形变掩盖比例问题；不能靠细线增殖、V纹、宽叶平片、分段覆皮或路径数量冒充原生体积。不能标准全套用一种AI设计，混搭时暗换另一套原生商品获得100。

尾/翼/角/耳/发束的根部必须在有效短裙、露腰、短发及单层佩戴时成立。先读完整参与层及作者来源说明；有意跨back/effect分层不得误判缺失。兼容manifest有效、12目标齐备或原路径同SHA，仅证明相应结构/来源，不证明艺术通过。

## 5. 历史、缺失证据与用户删除

- 历史分只对应原输入、原模型和当时实际看过的范围；同SHA不证明旧审阅没有漏审，旧accepted不免除本次复核。
- 确认旧漏审时保留仍存在的旧报告，另记发现、原部位、源对照和当前影响，不篡改旧分，也不假称本轮新增。
- 用户删除归档后尊重删除，不自动恢复、重建或用摘要补回旧证据。先核对runtime/当前results/workspace仍有哪些可用输入；缺失项标不可复核/待新审，不将历史分改成0。
- 当前文件与哈希即使相同，若缺少原case、完整参照或有效浏览器证据，也只能声称仍可验证的部分。若新任务授权补证，以新评审记录说明重新生成的来源，不冒充原历史材料。
- 保留本次评分必要的输入绑定、实际case ID、有效截图、排除记录及报告；历史保存规模按用户要求，不擅自重建大批已删除归档。
- 旧冻结模型/规则不可被最新模型/规则覆盖；当前规则修订不追溯篡改旧分。新的评分报告记录实际采用的规则版本。

## 6. 结果签发

每角色报告已审最低融合、身份、标准体局部/完整状态、pose/hue审计、有效case集合、未审与排除项、独立评委及来源SHA。只有全部门槛和完整覆盖满足才写accepted=true。

发布器仅校验数值、哈希、版本和覆盖，不代评、不补分。无观察时分数留空/null；部分报告只记实际有限数值，并明确accepted=false。不得为了通过发布器格式填0、98或伪造20源/7视图已审列表。

角色完整接受不等于七位整体完成；只有七位当前指定输入都满足门槛，且所需产物可用，才能声明整体接受。阶段停止是另一种结果，必须与完成区分。
