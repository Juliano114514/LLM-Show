# 图层、底板与生成部件契约

这是针对当前素材库的兼容方案。画布与默认边界来自本地解码；默认层序参考 QQ Show 2000 当日公开实现，互斥策略与接入字段是本包建议。当前本地目录没有应用源码，本文不意味着已经修改或验证任何换装引擎。

## 1. 主画布与锚点

- 原生画布 `width=140, height=226`，左上原点 `(0,0)`，x 向右、y 向下。
- 常规图层都以完整画布叠放，左上对齐；透明留白是定位信息。不要按可见内容包围盒居中。
- 画布放大时，对整棵图层树应用同一个缩放；原图不改。新组件预览可用 2 倍或 3 倍最近邻。
- 缩略图可以用单独的局部预览改善饰品识别，但局部缩略图不是可用于穿戴的源文件。
- 存量异常尺寸先隔离适配；未经验证不作“拉满画布”“自动居中”“自动裁边”等处理。

默认人物的近似连接位置，用于观察与新画辅助，不替代参考图：

| 部位 | 默认观察区域/位置 | 使用限制 |
| --- | --- | --- |
| 脸部 | alpha 范围 `x=50…88, y=50…87` | 面部与前后发沿同一参考叠合 |
| 头颈连接 | 约 `(70,87)` 附近 | 接缝应在真实图上检查，不靠点坐标保证兼容 |
| 肩部/上身 | 上装从 `y≈86` 开始 | 默认手臂可延伸至 `x≈30…108` |
| 腰胯重叠 | 默认上下装约 `y=120…134` | 不同裙/裤腰线不同，需检查重复皮肤或断层 |
| 脚底 | 默认约 `y=211` | 穿鞋、坐姿与礼服会改变此范围 |

默认 base 的几何参考可称作 `default-standing-v1`，这是本包新设的姿态族标识。坐姿、抬手、持乐器等分别命名，避免假兼容。

## 2. 默认层序

下表为从后到前的建议起点，沿用复刻站公开层级的相对顺序；编号仅有排序含义，**不是腾讯官方层编号**。实际物件如需跨越身体前后，优先拆层或声明例外。

| z | 本地类别/路径 | 说明 |
| ---: | --- | --- |
| 0 | `backgrounds` | 背景 |
| 1 | `background-decor` | 背景物、配角与后景光效 |
| 2 | `vehicle` | 大型车辆默认在人物后方 |
| 3 | `wings` | 翅膀在身体之后 |
| 4 | `back-hair` | 后发 |
| 5 | `bottom` | 下装及其身体部位 |
| 7 | `top` | 上装及其身体部位 |
| 8 | `outfit` | 整套服装与姿态 |
| 9 | `makeup` | 脸与五官 |
| 10 | `head-set` | 整套妆发，通常应与分体妆发互斥 |
| 11 | `front-hair` | 前发 |
| 11 | `neckwear` | 与前发同级时，用稳定次序将颈饰放在其后；必要时按领口拆层 |
| 12 | `earrings` | 耳饰 |
| 13 | `face-decor` | 脸饰 |
| 14 | `glasses` | 眼镜 |

## 3. 替换与恢复规则

为新组件或搭配清单采用下列明确状态；接入既有产品时先核实其现行行为，不能据此擅改产品状态机。

| 操作 | 推荐结果 | 需要保护的内容 |
| --- | --- | --- |
| 选 `outfit` | 隐藏 `top`、`bottom` 及其默认部件 | 套装本身提供的躯干、手臂、腿与鞋不重复绘制 |
| 从套装切到 `top` 或 `bottom` | 离开套装模式，恢复另一个上下装槽的已选项或默认项 | 不能让半个人或两套肢体并存 |
| 选 `head-set` | 隐藏分体 `makeup`、`front-hair`、`back-hair` | 保留原选择供切回；整头已含帽子时同时审视额外头饰 |
| 从整头切到分体妆发 | 离开整头模式；恢复脸和所选前后发组合 | 不叠加两张脸，不能只恢复头发忘记脸 |
| 选成对发型 | 原子替换前发与后发 | 同名只是候选匹配，先看图；不把其他发型的后发残留 |
| 选独立前发 | 明确后发是配套、显式无后发或保留已选后发 | 不自动加默认棕色后发 |
| 清除可选配饰 | 该槽变为“无” | 空层不能触发默认人物部件的误删除 |
| 清除核心身体/脸 | 回到相应默认项，或进入用户明确要求的空画布模式 | “清空配饰”“恢复默认人物”“完全空画布”三者需分清 |

套装自带翅膀、项链、手提包时，不按目录机械叠加同类物件。为其标明 `contains` 和 `conflicts`，必要时允许用户明确选择叠加，而不是声称所有组合天然兼容。

## 4. 新部件说明格式

可写成 JSON、YAML 或人能看懂的表格；不要求引入新框架。下面是**尚未生成的设计说明示例**，`file` 是建议输出名，不是已有素材：

```json
{
  "id": "new-pink-white-ribbon-jacket",
  "status": "design-only",
  "category": "top",
  "file": "generated/top/粉白蝴蝶结短外套.png",
  "canvas": { "width": 140, "height": 226, "origin": [0, 0] },
  "poseFamily": "default-standing-v1",
  "references": ["top/default.gif", "bottom/default.gif", "makeup/default.png"],
  "contains": ["upper-torso", "arms", "hands", "jacket"],
  "suppresses": ["top"],
  "conflicts": ["outfit"],
  "placement": { "x": 0, "y": 0, "scale": 1 },
  "alpha": true,
  "animation": { "kind": "static" },
  "compatibility": { "checkedWith": [], "notes": "生成后核对默认腰线和肤色" }
}
```

必要字段是类别、输出画布、姿态参考、身体包含范围、替换槽位、透明度和动画状态。不要为简单物品强制填不相关字段；也不要在 `checkedWith` 中列出未实际合成的资源。

前后发成对生成时另列 `frontFile`、`backFile`，说明它们共用的姿态/脸参考。长道具跨越身体前后时拆为两个文件并说明顺序，而不是从透明度猜遮挡。

## 5. 静态合成

1. 解析选择，先处理互斥，再补充缺失的核心默认部件。
2. 对每个素材读取真实编码、尺寸与解码状态。动画的静态预览声明使用哪一帧；首帧可能是空白或动作中间态。
3. 以共享原点和固定尺寸按层序 alpha 合成；不要重新居中各部件。
4. 透明 PNG、带背景的场景图、放大预览分别输出，按任务选择需要的产物。
5. 看原尺寸与放大结果，检查发际线、颈口、手臂、腰、脚、道具遮挡。

包内 [example-recipes.json](example-recipes.json) 的 `layers` 是显式完整的静态图层清单；不再自动补默认部件，否则会把默认四肢叠到套装上。它与“用户仅选择了几件物品，应用负责补默认”的输入模式不同。

## 6. 动画合成

- 先正确解码源 GIF 的局部帧与 disposal，得到每个时刻完整合成的帧；不能把增量块直接当独立全画布图。
- 保留原始每帧 duration 和循环信息；`loop=0` 表示无限循环，缺失 loop 不直接等于无限循环。
- 不同层按时间 `t` 各自取帧。只有等长等速动画才可以恰好逐帧对应。
- 默认选择有限的输出时长和合理采样间隔，并告知循环接缝是否连续。若源循环无法在合理长度内对齐，保留分层播放或接受并声明合成片段接缝，不强求无限公倍数。
- GIF 的 `0ms` 在播放环境中可能被归一化。新导出必须记录采用的最短时长策略并实际预览；不要默默删除帧或假设所有播放器一致。
- 解码失败的源文件先排除；不打开“容忍截断”来伪造完整动画。
- 输出仅为静态候选时，明确标记“动画尚未制作”。只有多帧文件实际生成并检查后才标记完成。

## 7. 检查范围

元数据解码证明文件能否被对应解码器读取，不能证明所有服装都能搭配。包内四组示例只验证已展示的静态首帧效果；没有执行浏览器交互、完整动画搭配回归或所有旧物品的两两组合。
