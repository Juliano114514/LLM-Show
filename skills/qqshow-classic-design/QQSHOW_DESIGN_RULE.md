# QQSHOW_DESIGN_RULE

经典二维 QQ 秀的设计语言、组件与内容规则。基于 `qq-show-classic/` 本地素材及联网研究整理，检查日期：**2026-11-09**。

**这套风格的中心是“能换装的细密像素纸娃娃，被装进一个表达个性的迷你闪图世界”。** 人物要有可辨识的发型、眼神与服装轮廓；装饰可以丰富，但仍要看见人、看清穿搭。

本文件是可单独阅读的主规则；具体坐标与替换约定见 [COMPOSITION_SPEC](references/COMPOSITION_SPEC.md)，真实文件名见 [ASSET_CATALOG](references/ASSET_CATALOG.md)，可直接改写的提示词见 [GENERATION_RECIPES](references/GENERATION_RECIPES.md)。

## 1. 适用边界与证据等级

| 标记 | 含义 | 使用方式 |
| --- | --- | --- |
| 本地事实 | 实际文件、解码结果、默认部件、已查看的图板 | 决定当前资源的尺寸与兼容边界 |
| 视觉归纳 | 观察本库代表素材得到的造型与材质特征 | 作为经典风格的主要方向，允许库内分支 |
| 外部依据 | 有链接的站点或设计文章 | 只支持原文覆盖的范围 |
| 建议约定 | 为后续生成与接入设定的默认值 | 可按用户目标调整，不冒称腾讯官方规范 |

本库不是所有年代、性别、身体比例与姿态的完整样本。默认人物可用于校准当前资源，不能据此宣称所有经典 QQ 秀都只有一种身材。

研究中的“大头贴 / purikura、闪图 / blingee、明亮颜色、丰富装饰”来自复刻项目自己的说明，并与本库的装饰资源相互印证。[QQ Show 2000](https://qqshow2000.com/)

QQ 系统默认头像、2019 年像素重塑、漫画再设计、厘米秀、超级 QQ 秀分别有各自语境。2019 年文章可以启发如何保留轮廓与个性，**不能把它的 5px 像素块或配色数量直接套到本库 `140×226` 换装图层上**。[腾讯 ISUX：玩转像素复古](https://isux.tencent.com/articles/qq-headshot)

## 2. 风格识别的六个支点

| 支点 | 应出现的视觉信号 | 常见偏离 |
| --- | --- | --- |
| 细密像素 | 小尺度清晰轮廓、像素簇、高光点、局部色阶 | 把低分辨率直接变成粗大 8-bit 方块 |
| 纸娃娃人物 | 大眼、小鼻口、明显发型、相对修长的身体 | 默认改成两头身婴儿比例或写实模特 |
| 换装逻辑 | 头、上下装、套装、饰品沿共同底板组合 | 每件漂亮但尺寸与姿态互不兼容 |
| 千禧时尚 | 低腰牛仔、短上衣、叠穿、靴子、蝴蝶结、金属配件 | 全部替换成当代极简服装或未来机械装备 |
| 情绪装饰 | 心形、星芒、花、翅膀、宠物、杂志贴纸、心情短句 | 只有抽象渐变，缺少社交表达 |
| 局部闪动 | 眨眼、亮点、飘落、灯光与道具的小循环 | 用整幅缩放、镜头运动、全屏白闪代替 |

这些支点不要求每件单品全部出现。例如简洁墨镜只需保持尺寸、轮廓和材质，不能给每件饰品都强加翅膀与星星。

## 3. 人物、发型与服装

### 人物比例与姿态

- **复用时以底板为准。** 默认合成人物约从 `y=45` 到 `y=211`，脸部约 `x=50…88, y=50…87`。这是当前样本的位置，不是任意新姿态的通用解剖比例。
- 视觉上是大眼、相对较大的头与纤细四肢；默认样本约四头身上下，长腿比两头身玩偶更接近本库。实际换装应直接沿参考图轮廓，不靠比例公式重建。
- 面部以眼睛与睫毛承担表情，小鼻、短嘴、少量腮红或眼影辅助。保留几像素的眼神差别，不把五官全部柔化成通用 AI 动漫脸。
- 常见站姿面向观者，略有倾斜或重心变化；坐姿、持物、抬手等视作独立姿态族。改姿态通常意味着连带修改衣服与身体，不能只移动头部。

### 头发

- 先画可辨识的外轮廓，再分大块发束与亮带；可用深棕、金棕、白金、粉紫、黑色等库内方向。
- 亮部是沿发束的细窄色阶与像素簇，不是覆盖全头的摄影镜面反光。
- 长发可能横跨脸后、肩后与身体前方；按遮挡需要拆为后发与前发。不要让整块长发压在脸上或穿过衣领。
- 先查是否存在同名后发；本库只有部分发型配成双层。无同名文件不代表该发型一定缺件，需看实际图像。
- `head-set` 通常已经画好脸、头发及部分头饰，适合整头替换。设计新整头时声明它包含哪些元素。

### 服装与材质

- 造型优先于纹理：短外套、吊带、喇叭裤、百褶裙、叠裙裤、靴子等要在原生尺寸读得出来。
- 牛仔：蓝灰或靛蓝主面、浅色折痕、深色缝隙、少量亮点；破洞与裤链集中放置。
- 缎面与礼服：清楚的褶皱明暗面与折线亮带，裙摆保留轮廓；不用大面积连续空气刷渐变。
- 金属与宝石：深边、亮面、一个白色或淡色尖锐高光；体积较小时用几个像素说明材质即可。
- 蕾丝、毛绒、薄纱：用有节奏的边缘与稀疏纹理表现，不在小区域灌入难辨的照片纹理。
- 上装、下装和套装经常自带皮肤、手臂、腿、脚或道具。新增部件先说明身体包含范围；鞋不应被假定为独立资源槽。

## 4. 像素、轮廓、颜色与光

### 像素密度

- 主画布默认为 `140×226`，原点在左上。保留完整透明画布，输出另附放大预览，不以放大图代替原图。
- 细节以原生约 1 像素为基本单位；主要轮廓常为一至数像素的深色或同色系暗边。不是所有轮廓都必须纯黑或一样粗。
- 斜线与曲线保持成组、连续的像素台阶。不要把高分辨率插画简单盖上马赛克滤镜就交付。
- 库中可见细密色阶、抖色和局部抗锯齿；保留这些差异，不强制每件资源成为无抗锯齿的硬边 16 色图标。
- 预览优先整数倍最近邻，例如 `280×452` 或 `420×678`。响应式布局可缩放整个画布，但各层必须共享同一变换，避免分别缩放产生错位。

### 颜色策略

以下是**建议色板**，用于建立色彩关系；不是全库量化结果，也不是官方色值。复用旧素材时优先从实际参考取色。

| 角色 | 示例色值 | 使用位置 |
| --- | --- | --- |
| 轮廓深色 | `#3B2238`、`#251E34` | 发束、衣缝、眼部、饰品暗边 |
| 亮粉与桃粉 | `#FF4FA3`、`#FFB8D9` | 可爱服饰、爱心、花、装饰标题 |
| 天蓝与冰蓝 | `#6BCFFF`、`#C7F3FF` | 牛仔高光、天空、翅膀、钻石 |
| 紫色组 | `#8A65D6`、`#D9B8FF` | 梦幻场景、边框、夜色 |
| 金黄组 | `#FFC83D`、`#FFF2A6` | 金属、皇冠、星芒 |
| 肤色组 | `#FFE0B4`、`#D9915C` | 新绘皮肤示例；优先匹配现有脸与身体 |

- 每套先选一个主色组，再加一到两个辅色与少量高光；这是搭配起点，不是对旧 GIF 的调色板上限。
- 可以高饱和，但让脸、发型与衣服主轮廓有明度差。黑白、深色摇滚、素色日常也属于库内方向。
- 不强制所有肤色、性别与角色共用默认人物；已有素材组合时注意脸、手臂、腿的肤色一致。
- 新部件的亮面方向应匹配相邻参考。没有共同参考时可采用偏上方来光作为起点，但不得称为全库统一光源。

## 5. 场景、装饰与构图

- **人物舞台**：人物通常居中，背景负责情境；发型、眼睛与服装不能全被高亮道具淹没。
- **三层阅读**：先识别人和穿搭，再读身边主题物，最后读边缘文字、花和闪点。极繁的关键是有主次。
- **背景语汇**：花园、樱花、城市、海边、城堡、舞台、梦幻岛与夜景。允许细密风景，也允许简洁抽象背景，不要求每张都满铺图案。
- **背景装饰**：在人物之后增加光环、落叶、舞台或陪衬；本库该目录也有完整配角，不能把它理解成只有抽象粒子。
- **边框**：花藤、珠链、星星、蝴蝶结、帘幕、相册边。保持中心可视，不做横跨双眼的厚边。
- **翅膀**：默认在身体之后；先检查套装是否已含翅膀，避免四翼或肩背重影。
- **宠物与道具**：常放脚边或侧边，保持人物与宠物头部错开。目录名只提供默认用途，实际遮挡仍以图像为准。
- 建议先让面部周围一小圈保持清楚，再向左右边缘和上下角堆装饰。面部保护区按所选姿态调整，不将默认坐标强套到坐姿。
- 杂志封面型文字可以占据更多边缘空间，但人物脸和标题必须同时可读。

## 6. 动画与透明背景

- 本地有 621 张多帧图像；头发、服装、背景、文字也可能动。以解码结果判断，不能只按分类或扩展名判断。
- 保留现有 GIF 的帧顺序、每帧时长、循环次数及 disposal 语义。首帧不代表整个动画的活动范围。
- 新闪效建议从 2–8 帧的轻量循环开始；眨眼安排“长停留 + 短闭眼 + 复位”，不要让所有帧等时导致抽搐。这是新内容的建议，不是全库帧数上限。
- 人物底板与脸的位置稳定，通常只让星点、眼睛、发梢、裙边或水面局部变化。
- 静态 PNG 使用真正的 alpha；GIF 只有索引透明能力，不能假设连续半透明能原样保留。需要薄纱或柔光时明确目标格式与背景。
- 棋盘格只是透明预览底色，不能烘焙进导出的图层。浅底、深底都要看边缘是否留白边或黑边。
- 多个动画合成为一个文件时按实际时间线采样，不按“第 n 帧对应第 n 帧”合并，也不为求所有循环公倍数无限延长输出。具体时间策略见组合规范。
- 用户偏好减少动态时使用静态代表帧；只有生成了实际多帧文件并检查后，才交付为动画。

## 7. 文字与命名

- 物品名可用“主题/颜色 + 结构 + 单品”，如“粉白蝴蝶结短外套”“星夜蓝钻边框”。说明它是新创作，避免假称历史绝版或官方限量。
- 心情文字以短句为主：等待、心动、耍酷、出游、朋友与自我表达；点缀爱心、星号、少量英文即可。
- 建议每个主标题约 2–8 个汉字，原生画布一次只强调一条。杂志风可以增加小字，但小字承担纹理时不要伪装成必须可读的信息。
- 可用细描边、阴影、双色字或珠光闪点；字形结构要完整。关键中文建议后期用实际字体排版，避免图像模型生成错字。
- 对话与物品操作保持直白，例如“试穿”“换一件”“保存装扮”“今天穿什么”；不要为怀旧牺牲可理解性。
- 本库包含字体文件，但没有附带可验证的完整授权说明。字体选择与分发遵循实际授权，不因文件存在就默认可公开再分发。

## 8. 配套 UI 的设计规则

**UI 与人物美术分别取证。** 下面的界面方向来自本地 `screenshots/opengraph.png` 中的 QQ Show 2000 复刻站；它不是早期腾讯商城截图。

- 总体结构可用“人物预览 + 物品网格 + 分类入口”，工具栏靠近预览，当前选择有明显标识。
- 使用蓝紫标题栏、浅灰底、亮色渐变容器、薄边线与轻微凸起按钮；物品卡保持中性，让素材自己承担色彩。
- 物品卡包含固定预览区域、短名称与可见选中态；整图按比例缩略。为了看清小饰品可另做局部预览，但不能修改主画布素材的定位。
- 选中同时表现边线/底色与勾选，不只靠颜色。复古样式可以保留，文字对比度、焦点态、触控区域仍按实际使用场景保证可用。
- 内容小圆角、描边与轻浮雕可作为建议；不要把整站替换成超大留白、毛玻璃、胶囊按钮与巨幅写实插画。
- 位图文字可用于小标题和装饰；说明、长物品名与主要操作优先可读字体。放大整个 UI 时不要把正文当作位图一起放大。

## 9. 可复用风格分支

以下是为使用本规则建立的**工作分组**，不代表腾讯历史商城分类。

| 分支 | 人物/服饰 | 场景/装饰 | 控制点 |
| --- | --- | --- | --- |
| 甜酷日常 | 粉白短外套、百褶裙、牛仔、卷发 | 樱花街景、小宠物、少量爱心 | 保留服装结构，不把所有物体都染粉 |
| 街头摇滚 | 刺猬头、叠穿、宽牛仔、链饰 | 夜城、星星、杂志标签 | 深色大形与金属小亮点形成对比 |
| 梦幻礼服 | 公主裙、纱、钻石、花饰 | 城堡、花园、翅膀、珠链 | 肩颈与脸清楚，裙摆不要压扁 |
| 黑白情绪 | 深色发型、黑白服装、简洁妆容 | 星夜、黑白边框、短情绪句 | 深色也有层次，不靠满屏霓虹解释 Y2K |

## 10. 交付验收

只检查与本次产物有关的项，报告真实状态：

- [ ] 原生尺寸下，脸、发型、衣服主轮廓与主题能辨认。
- [ ] 新图层画布、透明度、坐标、姿态族、身体包含范围已说明。
- [ ] 没有逐件裁边居中、强行拉伸、重复脸、重复手脚或肤色接缝。
- [ ] 套装、上下装、整头、分体头发的替换关系可执行。
- [ ] 浅深底与整数倍放大预览已查看，导出无棋盘格或意外底色。
- [ ] 关键中文逐字核对；可读文本没有被闪光吞没。
- [ ] 动画若存在，实际解码检查了帧数、时长、首尾、边缘与遮挡。
- [ ] 新创作与旧素材、实际产物与提示词、已验证与待验证已区分。

如果只交文案或提示词，将像素、穿戴、动画条目标为“尚未生成，待验证”，不为了填满清单而编造通过结果。
