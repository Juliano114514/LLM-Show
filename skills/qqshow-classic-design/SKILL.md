# 经典 QQ 秀设计与内容生成

将真实素材作为造型与对齐依据，生成能接入同一套换装体系的内容。核心语汇：**小画布、细密像素、大眼纤身、服饰拼装、亮色高光、大头贴装饰与局部循环闪动**。不要仅凭“Y2K”一词发挥。

## 工作方式

1. **定位素材根目录。** 本包在当前工作区时，默认候选为相对本 skill 的 `../../qq-show-classic`。用户指定的 `assetRoot` 优先；移动 skill 后重新定位，不把本机盘符写进产物。找不到资源时说明缺少的依赖；纯文字任务可继续输出设计方案，不能宣称看过缺失素材。
2. **明确输出对象。** 用户没限定时，以经典二维模式、当前素材比例、原生 `140×226` 主画布为起点。分清“完整场景”“可替换图层”“配套 UI”；不把衣服画成带头发、背景的成品海报。
3. **找 3–5 个具体参考。** 至少包含目标类别的一张真实素材；可穿戴部件再包含默认身体或目标套装，场景包含人物占位。说明借鉴的是轮廓、位置、材质还是色彩。不要用文件名代替看图，也不要从文件名猜动画。
4. **先复用，再补缺。** 现有资源满足目标时直接组合。新增部件保留底板位置；需要改姿态时将其作为独立姿态族，不冒称能兼容所有旧部件。
5. **按模式落地。** 用生成配方写清内容、参考、透明度、像素密度与禁用方向。图像工具只能给出大尺寸或静态图时，将其视为候选稿；后续像素整理、对齐、动画制作未完成前，不称为可直接换装的部件。
6. **看最终输出。** 静态资产至少检查原生大小、整数倍放大、浅深背景与完整合成；动画另检查合成帧、持续时间和首尾衔接。只有实际完成的检查才记为通过。遵守用户的验证范围，不主动编写测试代码。

## 不可丢失的约束

- 大多数素材的透明留白就是定位数据。主画布中按原始坐标放置，不能逐件裁边后居中，也不能让每个小部件分别 `contain` 到画布。
- `default` 不等于空：五张默认素材共同构成人物；`top`、`bottom` 常包含手臂、腿和脚。没有独立裸模资源时不要虚构裸模依赖。
- `head-set` 在本库指**妆发造型**，不是耳机；通常同时包含脸与头发。与分体头发、妆容的组合需明确互斥。
- 套装与上下装、整头与分体头发使用明确替换策略；不能靠堆叠掩盖重复肢体或双层脸。
- 三张异尺寸图层和一张扩展名与编码不符的资源见素材目录；检测真实编码，异常图不做无依据拉伸或偏移。
- `screenshots/opengraph.png` 是复刻站截图，不是腾讯早期官方 UI 规范。2019 年的 QQ 系统头像项目也不是经典 QQ 秀的图层制作规格。
- 本包提炼的是设计方法与本地兼容约定，不提供素材或字体的额外授权；需要对外使用时沿用项目已有授权范围。

## 建议输出格式

按任务裁剪，不为小任务制造额外文档：

- 设计目标与风格分支，一两句即可。
- 使用的真实素材路径，或新增内容的具体参考。
- 图层/部件说明：画布、姿态、包含的身体区域、替换槽位、透明背景、动画状态。
- 实际生成的产物及预览；如只交提示词，明确它仍是提示词。
- 已检查项与尚未完成项，尤其是原尺寸像素质量、穿戴兼容与动画导出。
