# 标准立绘姿态素体：融合度的独立必审子项

这是原用户素体验收要求的落实，属于融合度①，不以混搭用的原生姿态兼容件替代，也不新增第三个总评分维度。全套服饰遮住问题，或兼容body原曲线同图100，都不能证明标准立绘姿态的定制素体达到98。

2026-11-10追加：独立报告必须逐角色核对标准图可见的躯干、肩肘腕/掌心、髋膝踝、腿部交叉及重心，列出显著差异及扣分依据。非常显著的素体/四肢动作差异令 `poseConsistent=false`，本子项不得通过；身份动作20分项也须解释影响。身体文件与旧稿相同、原生曲线来源或旧98分均不能免审。遮挡关节保留不确定性；混搭兼容稿按原生目标姿态另审。详见 [评分细则](SCORING.md)。

## 固定证据

先检查当前评分输入和资料可用性。用户已删除results/archived，下面命令只是已有生成器的调用格式，不是要求恢复该目录；缺少该轮cases/session时不能运行并声称完成。可用runtime快照与已发布study只支持实际仍存在的证据范围；若任务授权补证，另立明确的新评审记录，不伪造原历史来源。

```powershell
node LLM-show-fashion/tools/remake/render-standard-study.mjs --round=N gpt
```

只读取该轮冻结目录及cases。新模型直接使用同版成装的完整 `body` 层、头脸和 `anatomy.hands` 裸掌，保留作者在 body 中的实际遮挡与paint顺序；构建器同时核对6个非手解剖分件确实包含在该body中。不能把7件按统一顺序重排后称为相同身体。手势不被原生目标pose变体替换。生成 `results/archived/rounds/{id}/round-N/standard-study/`，已有study.json时拒绝覆盖。

历史R1–9的冻结模型及图保持原来的7件排序，React也用对应旧模型重放。层序审计单独放在各轮 `stack-audit/`，附真实body重合图及通道差异；通道差异不是审美分。旧分数只覆盖其原图，是否影响结论须由独立judge看审计图决定。新模型及新图必须开新轮次，不能用新图冒充旧评分证据。

- `standard-mannequin.png`：标准姿态完整素体。
- `standard-body-contexts.png`：与本轮5种原生素体并排，无服饰/鞋/道具遮挡。
- `standard-vs-reference.png`：标准立绘与完整素体的姿势比较。
- `standard-vs-20-1..4.png`：20个原始SWF首帧各与该素体同倍率并排。
- `sources/`及`study.json`：原帧副本、原SWF SHA、可见覆盖范围、全部新图SHA、角色input/native/model/seed。

后续新轮另附 `standard-mannequin-6x.png`：按同一冻结矢量与paint顺序直接以6倍尺寸渲染，不放大2倍PNG。`study.detailViews`记录其SHA与来源；它是补充细节证据，不混进固定7视图或20原SWF计数。独立judge逐处查看可见的颈肩、双肘、双腕/掌根、腰髋、双膝和双踝的轮廓/色面接续，并在报告中引用该图和SHA。服饰遮住或不确定处仍不作隐藏解剖推断。

跨两个原件重组后暴露的矩形切边、平截锁骨或套筒接面属于当前AI组装的问题；原母件固有的paint/画风仍按原生100定义，不把原件自身细节当成AI新接缝扣分。若放大补审发现旧稿已有的漏审，应保留旧轮报告，在新报告中明确发现轮次、原有部位、源对照及归属，不假称本轮新增回归；同文件SHA或旧98不能代替看图。

先一次性核完双侧可见接面，再给返修清单：左右颈肩、左右肘、左右腕掌、腰髋、左右膝踝逐项列为“已看且连续”“确认问题”或“遮挡/未知”。不只查上一轮指出的那一侧。将完整436、正确默认436+448和当前重组肩并排，可区分原生短封端与新臂未接、双橙边、空隙等组装缺陷；不可删原母源线、移动整条肢体或靠袖子遮住来代替根部修复。

本期正式验收还须在内置浏览器按同冻结SVG顺序呈现裸标准体及原生/立绘/20源对照。6倍细节应由浏览器实际SVG层直接呈现或有明确来源的浏览器高倍取证，不能只把离线2倍PNG放大。辅助离线6倍图与浏览器证据分别留存。当前报告说明实际浏览器覆盖、呈现者和独立审阅者；未看关节/源保持未知，不用旧98或保护SHA补齐。

为适应正常视窗，6x可分为三个直接SVG横带：840×452、原始y范围0–452、452–904、904–1356，不缩放，不改源或paint顺序。三带必须实际审完才计完整6x；未看条带保留未覆盖，条带不增加固定7视图/20源计数。保存位图若仍加载中或被截断，即使DOM为ready也不计覆盖。

是否返修及是否创建新轮以当次任务授权和停止指令为准。只评分时登记问题，不自动改图；上期39停笔记录是历史状态，不是本子项的永久轮次门槛。

20样例含局部与着装，不能从其透明/被遮区域臆测身体，不能称20套完整裸体。躯干/肢体材质只比较真实可见区域；服饰和发型只作Fashion整体语境。姿态允许与立绘神似，不要求和五个随机原生pose相同。

## 独立报告

独立judge可先出部分审阅报告，但必须列实际看过的视图、原源ID、6x条带与未覆盖项。只有7固定视图、20原帧和直接6x都实际审过，才可签完整通过。报告通常写入 `ai-workspace/workspace/reviews/{id}-standard-body-round-N.json`；不能由绘制者自评，不能用算法差值或旧98填未审。

```json
{
  "protocol": "fashion-standard-body-98-v1",
  "character": "gpt",
  "round": 4,
  "inputHash": "从cases/study读取",
  "nativeHash": "从study读取",
  "renderModelHash": "从study读取",
  "seed": "从study读取",
  "studyManifestSha256": "实际study.json字节SHA256",
  "integrationScore": null,
  "poseConsistent": null,
  "pass": false,
  "reviewedReferenceIds": [],
  "reviewedViews": [],
  "issues": [],
  "evidence": []
}
```

示例null/空列表为未审准备单，不是可直接发布的评分JSON；现有发布器要求有限数值时，不得为了校验填0或98。实际已看局部可以给真实局部分，但报告须写“所见局部98，覆盖不足”，pass=false，并只列真实已审项。pose未审为未知，不能冒充显著不一致。

按现行SCORING五项融合细则给实际所见最低分；对照5原生及20原帧分别写判断、坐标、扣分与修法。完整子项须融合≥98、poseConsistent=true、pass=true、20原源和7视图齐备、直接6x完整且有效IAB审阅范围齐全。机器格式正确不补足实际缺失覆盖。

发布器核对hash与覆盖，不生产审美分。完整246混搭案例通过、全套立绘/MD还原≥90、此标准素体子项通过，才写角色accepted=true。单件或兼容身体100不能代替。React的「③标准姿态素体」仅是审阅视图，使用该轮标准body/裸掌及冻结模型，不调用native目标兼容身体。

获准返修时，将此组图、素体独立报告及普通混搭反馈一起交对应refiner；新输入另行独评。仅评分或用户已停手时保留建议，不自动改稿。仍存在的旧图/报告不覆盖，用户已删除的归档不自动恢复。

React素体视图直接显示本轮四张「每五个原SWF×当前素体」冻结对照板，可点开放大，并链接study.json中的逐源覆盖与SHA。只有当前input/native/model/round匹配的评分及study才展示，不把旧body分带到新图。另可打开20套完整原生组装搭配的补充总板（nativeHash须相符）；它与20个原始SWF首帧分开标注，不声称额外恢复20套原始成套。
